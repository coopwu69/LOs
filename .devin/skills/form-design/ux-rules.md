# Form UX Rules

- เริ่มด้วยชื่อฟอร์ม วัตถุประสงค์ เวลาที่ใช้ และวิธีใช้ข้อมูล
- หนึ่งหน้าควรมีหัวข้อหลักชัดเจน และใช้ heading hierarchy ไม่ข้ามระดับ
- เรียงจากคำถามง่ายและไม่อ่อนไหว ไปหาคำถามซับซ้อนหรืออ่อนไหว
- แสดงความคืบหน้าเมื่อฟอร์มมีหลายขั้น และอนุญาตย้อนกลับโดยข้อมูลไม่หาย
- ใช้ label เหนือช่องกรอกเพื่อรองรับมือถือและข้อความภาษาไทย
- ทำเครื่องหมาย optional ให้ชัดเจน หรืออธิบาย required อย่างสม่ำเสมอ
- Validation ควรเกิดเมื่อ blur หรือ submit ไม่ขัดจังหวะขณะกำลังพิมพ์
- Error ต้องบอกว่าเกิดอะไร เหตุใด และแก้อย่างไร พร้อมเชื่อมด้วย `aria-describedby`
- เมื่อ submit ล้มเหลว ให้คงข้อมูลเดิม โฟกัส error summary และลิงก์ไปช่องที่ผิด
- เป้าหมายกดอย่างน้อย 24×24px; primary action แนะนำ 44×44px
- รองรับ keyboard, visible focus, screen reader, zoom 200% และ WCAG 2.2 AA
- อย่าใช้สีเพียงอย่างเดียวเพื่อสื่อ required, selected, correct หรือ error
- บันทึกร่างหรือเตือนก่อนออกเมื่อฟอร์มยาวและข้อมูลยังไม่บันทึก
